# ResilAI Documentation Architecture

**Objective:** Create a documentation architecture that separates Product Documentation from Customer Evidence/Documents.

## 1. Information Architecture (L1/L2/L3)

### L1: Executive Briefing (Business Workspace)
- **Goal:** 30-second time-to-insight.
- **Pages:**
  - `/morning-brief`: The "Today" page. North Star status, AI Narrative summary.
  - `/needs-attention`: Immediate, high-priority operational blockers.
  - `/recovery`: Business continuity, backup status, RTO estimates.

### L2: IT Operations (Operations Workspace)
- **Goal:** Technical drill-down and evidence verification.
- **Pages:**
  - `/operations`: IT Workspace overview.
  - `/activity/compliance-drift`: Real-time compliance monitoring.
  - `/technology/intelligence`: Tech stack lifecycle and vulnerability data.
  - `/activity`: Evidence network graph and raw connector logs.

### L3: Administration & Documentation
- **Goal:** Platform configuration and knowledge base.
- **Pages:**
  - `/settings`: Organization and user settings.
  - `/connectors`: Telemetry source configuration.
  - `/documents`: Customer Evidence (Certificates, BAA, Policies).
  - `/docs`: Product Documentation (How ResilAI works).

## 2. Recommended Documentation Navigation

### A. Product Documentation (`/docs/*`)
Explains *what ResilAI is* and *how it works*. It is publicly accessible (or available to all users) and focuses on the platform's methodology.

- **Overview:** Introduction to the Connect → Verify → Understand → Act loop.
- **Dual-Engine Architecture:** Explains the boundary between the Deterministic Verification Engine (math/rules) and the Gemini Business Impact Engine (narrative).
- **Evidence Architecture & Trust Model:** How telemetry is ingested, normalized, and scored without human manipulation.
- **Regional Profiles:** How regulatory rules (HIPAA, GDPR) are applied based on clinic location.
- **Integration Model:** How to connect Wazuh, Splunk, Azure AD, etc.

### B. Customer Evidence / Documents (`/documents/*`)
Private to the tenant organization. Contains artifacts generated by or uploaded to ResilAI for compliance purposes.

- **Generated Reports:** Board-level PDF exports, Monthly Readiness Summaries.
- **Compliance Artifacts:** SOC2 mappings, HIPAA risk assessments.
- **Legal/Vendor Docs:** Business Associate Agreements (BAA), Vendor Risk Assessments.

## 3. Top 10 Product Comprehension Problems

1. **"Is this just a dashboard or a scanner?"** Users confuse ResilAI with a vulnerability scanner because the documentation doesn't clearly explain the "Verification Engine" concept (verifying existing tools, not scanning).
2. **"Where do the scores come from?"** Hardcoded UI fallbacks obscure the actual deterministic math.
3. **"Is the AI grading my security?"** The UI conflates Gemini narrative generation with deterministic scoring, making users distrust the score.
4. **"How do I fix this?"** The path from "Needs Attention" to actual remediation steps is fragmented.
5. **"What's the difference between Operations and Dashboard?"** The legacy routing duplicates information across different pages.
6. **"Are my documents public?"** Mixing Product Docs (`/docs`) with Customer Evidence (`/documents`) in the UI causes data privacy anxiety.
7. **"Is this live data?"** Missing "Last Synced" timestamps on critical telemetry graphs.
8. **"What happens if a connector breaks?"** The UI fakes a 98% confidence score instead of showing a degraded state, leading to false trust.
9. **"Who is this for?"** The current UI tries to serve the CISO, the IT Admin, and the CEO on the same screen.
10. **"What is the Connect → Verify → Understand → Act loop?"** This core product philosophy is entirely absent from the user onboarding flow.
